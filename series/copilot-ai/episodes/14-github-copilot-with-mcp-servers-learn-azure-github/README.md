# DEVLADLOG Copilot & AI #14 - GitHub Copilot with MCP Servers (Learn, Azure, GitHub)

Same Contoso vendor team as [episode 13](../13-github-copilot-in-vs-code-agent-mode-instructions/), now with tools
instead of guesses: GitHub Copilot in VS Code connected to three **official MCP servers** (Microsoft Learn, Azure,
GitHub) and to **one we wrote** (Contoso vendor renewals, Python, stdio). The episode also covers the part nobody
puts in the quick start: VS Code now has **two MCP configuration formats** (`.vscode/mcp.json` with `servers`, and the
native `.mcp.json` with `mcpServers`), secrets cannot be prompted in the native one, and "read only" is a setting you
choose per server.

What was built (and runs here):

- **`src/vendor_mcp/`**: an MCP server with three read-only tools (`list_renewals`, `get_vendor`, `total_cost`), built
  on the official Python SDK, started as a real subprocess by the tests and spoken to over stdio.
- **`src/mcpconf/`**: `check` and `convert` for MCP configuration files: finds literal secrets, undeclared or unused
  `${input:...}`, editor-only fields in native files, unpinned `@latest`, plain http, GitHub/Azure servers that are not
  read-only; converts `.vscode/mcp.json` to `.mcp.json` (input prompts become `${ENV_VAR}` references, `${env:X}` becomes
  `${X}`, `oauth.clientId` becomes `oauthClientId`, editor-only fields are dropped and reported) and refuses to copy a
  literal credential.
- **The demo workspace is `src/` itself** (copy it to `C:\demo\mcp-demo`): `.vscode/mcp.json` (source),
  `.mcp.json` (generated by `mcpconf convert --add-tools-star`, a test asserts they match), `.github/` instructions
  (the Learn-recommended "use the docs tools" text, plus a rule to use our vendor tools).

## Run and test

```bash
cd series/copilot-ai/episodes/14-github-copilot-with-mcp-servers-learn-azure-github
python3 -m pip install -r src/requirements.txt       # mcp 2.x, PyYAML, pytest
python3 -m pytest -q                                  # 25 passed, 1 skipped
MCP_LIVE=1 python3 -m pytest -q -m live               # 1 passed: calls the public Learn MCP endpoint (internet, no sign-in)
cd src
python3 -m mcpconf check .vscode/mcp.json             # 0 errors, 0 warnings
python3 -m mcpconf check examples/bad.vscode-mcp.json # exit 1: literal token, undeclared input, ...
python3 -m mcpconf convert examples/github-pat.vscode-mcp.json
python3 -m mcpconf convert .vscode/mcp.json --add-tools-star --out .mcp.json
python3 -m vendor_mcp                                 # the server, waiting for an MCP client on stdin
```

Verified here: pytest **25 passed, 1 skipped** (Python 3.13, `mcp` 2.3.0, pytest 9). The one skipped test is the live
one, run separately: **passed** (the Learn endpoint listed `microsoft_docs_search`, `microsoft_docs_fetch` and
`microsoft_code_sample_search`, all with `readOnlyHint: true`). An unauthenticated request to the GitHub remote endpoint
returned `401` with an OAuth `WWW-Authenticate` header, as documented. **Not verified here:** the Azure MCP Server
(`npx -y @azure/mcp@...`) was not started in the build container (about 160 MB package and it needs your Azure
sign-in); only its configuration shape, flags and the npm version were checked against Learn and `npm view`. The GitHub
server was not signed in. Everything VS Code shows needs the recording.

## What we learned / gotchas

From Microsoft Learn, the VS Code docs (dated 18 Nov 2026) and GitHub's docs, read on 21 Nov 2026, except where marked.

- **Two formats.** VS Code's MCP reference: *for new Copilot configurations use `.mcp.json` (workspace root) or
  `~/.copilot/mcp-config.json` with top-level `mcpServers`, not `.vscode/mcp.json` or the profile `mcp.json`*, which use the
  deprecated Local harness's `servers` format. Eligible entries in those files are *forwarded* to Copilot sessions;
  entries that need `${input:...}` or `${command:...}` are rejected. The Learn and Azure quick starts (and GitHub's own
  README) still show the `servers` format and say "agent mode". Both are right for the Local harness; check which one you are in.
- **Variables differ.** Native: `${NAME}` / `${NAME:-default}`; editor: `${env:NAME}`, `${input:id}`, `${workspaceFolder}`.
  A bare `$NAME` is literal text in the VS Code MCP client. The native format has **no input prompts**, no `envFile`,
  no `dev`, no `sandbox`; "do not commit tokens, passwords, or populated authentication headers" and a config file "is not
  a secret store". For a static token the docs point to environment variables or OAuth.
- **`type` and `tools`.** The VS Code reference lists `type` as required in the editor format, while the Azure sample on
  Learn omits it (`mcpconf` warns). In native files `tools` is a list of tool names or `["*"]`; it limits what is
  available and "doesn't bypass tool approvals". Whether a native entry without `tools` works was **not verified**: the
  committed `.mcp.json` follows the documented examples and has `["*"]`.
- **Trust, authentication, tool choice and approvals are separate controls.** Workspace `.vscode/mcp.json` and `.mcp.json`
  inherit Workspace Trust: in a trusted workspace they start without a separate MCP prompt, and stdio servers can run
  code. Sampling has its own approval flow.
- **Microsoft Learn MCP Server.** Remote, streamable HTTP, `https://learn.microsoft.com/api/mcp`; no authentication, no
  charge, public documentation only; generally available since 2025-11-07 (release notes). It is not a browser endpoint
  (405 on GET). Tools "may change": clients should list tools at startup instead of hard-coding them; the endpoint takes
  `?maxTokenBudget=` to cap search results. Learn recommends an instructions file when the agent does not call the tool
  (`.github/instructions/microsoft-docs.instructions.md` here uses that text).
- **Azure MCP Server.** Needs a GitHub Copilot subscription and an Azure account; tools are disabled by default in
  supported hosts; it uses Entra ID through the Azure Identity library with your own credentials or managed identity,
  so Azure RBAC decides what works; Copilot does not ask you to sign in if the Azure CLI is already signed in. The local
  server is "intended strictly for developer use". Start options (Learn): read only, mode (`namespace` default,
  `consolidated`, `all`, `single`), namespace, tool. `@azure/mcp@latest` was **`4.0.0-beta.9`** on 21 Nov 2026
  (`npm view @azure/mcp`), and some Learn pages still say "Preview": pin the version.
- **GitHub MCP Server.** Remote `https://api.githubcopilot.com/mcp/` (OAuth by default, or a PAT in a header); add
  `/readonly` to a URL, or the `X-MCP-Readonly: true` header, for read-only tools; `X-MCP-Toolsets` and `X-MCP-Tools`
  narrow the tools. Plan: available to all GitHub users; individual tools inherit the access requirement of the feature
  (for example Copilot cloud agent tools need a paid licence). In an organization with Copilot Business/Enterprise the
  "MCP servers in Copilot" policy must be enabled. Enterprise Managed Users: PAT is off unless an admin enables it.
- **Python SDK 2.x (hit while building).** `mcp` 2.x renamed `FastMCP` to `MCPServer` (`mcp.server.mcpserver`) and the SDK
  says to pin `mcp<2` for v1 code, so `requirements.txt` pins `mcp>=2.3,<3`. An ordinary exception in a tool reaches the
  model only as "Error executing tool X"; raise `ToolError` (a test checks it) so the model sees the message and can retry.
  A tool returning a plain `dict` gave no structured content; a `TypedDict` return type does.
- **Windows:** the committed config says `"command": "python"`; the tests substitute the test interpreter. On the
  recording laptop check that `python` (not only `py`) is on PATH.
