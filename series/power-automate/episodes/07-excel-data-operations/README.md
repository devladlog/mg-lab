# DEVLADLOG Power Automate #7: 400 prices in, 256 imported

A **Supplier price list import** cloud flow for Contoso purchasing (the team from episodes 2, 3 and 5), and the
local material that proves it reads **every** row of an Excel table, rejects bad rows with a reason and writes the
whole list in **one Office Script call**, before it touches the tenant.

Every month Fabrikam, the office supplier, sends a workbook with a table **Prices** (`Item No.`, `Description`,
`Unit price`, `Valid from`). Purchasing drops it into the **Price lists** library on the Purchasing site. Then:

- **Trigger:** SharePoint *When a file is created (properties only)* on *Price lists*, trigger condition: the name
  ends with `.xlsx` (so the CSV of rejected rows the flow saves there doesn't start another run).
- **Read:** Excel Online (Business) *List rows present in a table* with **pagination on (threshold 5,000)** and
  **DateTime Format = ISO 8601**. If 5,000 rows or more come back, the run **terminates as Failed** (`TooManyRows`):
  the file may have more rows than the threshold, and a partial import is worse than none.
- **Shape and check without a loop:** one **Select** maps each row to `sku`, `description`, `priceText`,
  `validFrom` and a `problem` (empty when the row is fine): *Missing item number*, *Price has a comma: use a number
  cell*, *Price is not a number*, *Price must be more than zero*, *Valid from is not a date*. Two **Filter array**
  actions split valid and rejected rows; a second **Select** converts prices with `float()`.
- **Write in bulk:** *Run script from SharePoint library* runs the Office Script **Upsert prices**
  ([`UpsertPrices.ts`](src/officescript/UpsertPrices.ts)) against *Purchasing catalogue.xlsx*: it validates every
  row first (and throws, which stops the flow, before writing anything), keeps the last row when the supplier lists
  a SKU twice, reads the **Catalogue** table once, updates **every** row with a matching SKU, appends new SKUs, and
  returns the counts plus the price changes over 20 %. **Two writes** (`setValues`, `addRows`) whatever the size.
- **Report:** **Create CSV table** of the rejected rows, saved as `Price lists/Rejected/<file>-rejected.csv`;
  **Create HTML table** of the big changes; one summary email to purchasing.

Our first drafts fell into four traps: no pagination (256 of 400 rows, nothing said so), no DateTime Format (dates
as serial numbers), a column name typed by hand (`Item No.` comes back as `Item No_x002e_`) and Get/Update/Add a row
inside Apply to each (794 Excel calls against a budget of 100 per minute, and a duplicated catalogue row updated
only once). They are in [`variants.py`](src/excelfake/variants.py) and each has a test.

## Run it

Needs Python 3.10+, pytest, openpyxl (for the `.xlsx` tests) and **Node 22.13+** (runs the Office Script).
`pac` is optional (pack test skipped without it); the `tsc` test runs only after `npm ci`.

```bash
cd series/power-automate/episodes/07-excel-data-operations
(cd src/officescript && npm ci --no-audit --no-fund && npm run typecheck)   # tsc 4.0.3: no errors
python -m pytest                       # 39 passed in ~7 s (pac 2.16.1, node 22.23, TypeScript 4.0.3)
rm -rf src/officescript/node_modules

cd src
python -m flowkit lint solution/Workflows/*.json
python -m excelfake                    # the import as the solution does it
python -m excelfake --no-pagination    # draft 1: 256 rows read, nothing rejected, nothing new
python -m excelfake --serial-dates     # draft 2: 400 rows rejected, "Valid from is not a date"
python -m excelfake --unencoded        # draft 3: 400 rows rejected, "Missing item number"
python -m excelfake --row-by-row       # draft 4: 794 Excel calls, 1200 Power Platform requests
python -m excelfake --rows 6000        # a file over the threshold: run Failed, TooManyRows
python -m excelfake make-workbooks ../out   # the two lab workbooks
pac solution pack --zipfile ../out/PriceLists.zip --folder solution --packagetype Unmanaged
```

## How the material was made, and what still needs the tenant

The flow was written from the Excel Online (Business) connector reference (operation IDs `GetItems`,
`RunScriptProdV2`, `GetItem`, `PatchItem`, `AddRowV2`) and the SharePoint and Outlook connectors, packed with `pac`,
and dry-run with `flowkit` against `excelfake`. The Office Script is real TypeScript, type-checked with
TypeScript 4.0.3 and executed by Node; the workbook it runs against is a test double. **Needs tenant:** the
Purchasing site and libraries, the script saved in Excel, the flow saved and run on the real files, the export
(demo.md).

## What we learned / gotchas

- **256 rows, silently.** Learn: *List rows present in a table* "returns up to 256 rows by default. In order to get
  all rows, turn on pagination." Our first draft read 256 of 400 rows, ran green and emailed "0 rejected": the bad
  rows were all after row 256 (`test_without_pagination_only_256_of_400_rows_are_read_and_nothing_says_so`).
  Pagination keeps calling until it has all rows or reaches the threshold (5,000 for Low, 100,000 for others), and
  each page counts as a request. Because pages can overshoot the threshold, the flow fails when it gets **5,000 or
  more** rows instead of importing a part.
- **Column names come back encoded.** Learn: `.` becomes `_x002e_`, `@` `_x0040_`, `:` `_x003a_`, `#` `_x0023_`.
  Dynamic content uses the encoded name; an expression typed by hand with `item()?['Item No.']` gets null for every
  row (`test_a_column_name_with_a_dot_comes_back_encoded`). The linter flags it. Learn also says Filter Query,
  Order By and Select Query support only alphanumeric column names.
- **A comma is a thousands separator.** Learn's own examples: `isFloat('10,000.00')` is true and
  `float('10,000.333')` is 10000.333 in the invariant culture. So a price typed as text the Portuguese way,
  `12,50`, passes `isFloat` and `float` makes it **1250** (flowkit follows the examples; the exact .NET parsing is
  our inference, demo step 7 checks it). The flow rejects any price with a comma and asks for a number cell.
- **One Office Script call instead of a loop.** Excel connector throttling: **100 API calls per connection per 60
  seconds**. Our row-by-row draft made 794 calls (at least 8 minutes of budget) and 1,200 Power Platform requests
  for one file; every action in a loop counts (Learn, request limits). The script version makes 3 calls (two pages
  and the script) and 12 requests (`test_row_by_row_needs_794_excel_calls_and_misses_the_duplicate`).
- **Update a row changes the first match only** (Learn, known issues), and the key column name is case-sensitive.
  Someone had pasted FAB-0007 twice in the catalogue; the loop updated one copy. The script updates every match and
  reports `duplicateRowsInCatalogue`.
- **Office Scripts in flows have their own limits** (Learn, platform limits): Run script **3 calls per 10 seconds
  and 1,600 per user per day**, a **120-second** timeout for the synchronous call, parameters up to **30,000,000
  bytes**, Excel requests and responses **5 MB**, and **no external calls** (`fetch is not defined`). Office Scripts
  use **TypeScript 4.0.3**, no `any`, only arrow functions in array callbacks; the tests check all of these.
  `throw` stops the script and the flow (Learn, best practices), so the script validates everything first and
  writes nothing when one row is bad.
- **Text that starts with `=`, `+` or `-` is a formula.** Learn (`Range.setValues`): such values are interpreted as
  formulas. A supplier description like `- 10% promo` would become one; the script puts a space in front and
  counts it (`textsEscaped`).
- **Dates are serial numbers.** Excel stores 1 January 2000 as 36526 (Learn); the script writes `Valid from` as a
  serial number so the column stays a real date.
- **Connector facts that shape the design** (Learn): Excel Online (Business) is a **standard** connector; files up
  to **25 MB**; it only works with **tables**; a file can stay **locked up to 6 minutes** after the connector last
  used it; writes can take **up to 30 seconds** to show; simultaneous edits from several clients aren't supported
  (the linter refuses parallel loops writing to one workbook). Run script needs a **business Microsoft 365 licence**.

### What was not verified here

- **Designer conventions** not documented on Learn: the parameter keys `source`, `drive`, `file`, `table`,
  `dateTimeFormat`, `scriptSource`, `scriptDrive`, `scriptId`, `ScriptParameters/<name>`; the value `"ISO 8601"`; the
  pagination setting as `runtimeConfiguration.paginationPolicy.minimumItemCount`; the Run script output as
  `body/result`; SharePoint's `{Identifier}`, `{FilenameWithExtension}`, `{IsFolder}` trigger properties. demo.md
  step 6 exports the real JSON and replaces ours.
- **Value formats** of List rows: we assume numbers as invariant text (`12.5`), dates as the serial number unless
  DateTime Format is ISO 8601 (then `2026-12-01T00:00:00.000Z`), and a page size of 256 with pagination on. Whether
  Create CSV table quotes a value that contains a comma (`flowkit` quotes it, RFC 4180 style). demo.md step 7 checks
  each one in a real run.
- The exact .NET result of `float('12,50')` in the tenant (see the gotcha above).
