# DEVLADLOG Power BI #1 — Data Modeling & Star Schema

We take a flat sales export ("one big table", 4,071 order lines of fictional **Contoso Bikes** data) and turn it into a
**star schema** semantic model that Power BI Desktop opens as a Power BI Project (PBIP):

- a Python step splits the export into **one fact table and four dimensions**, with surrogate keys, a flattened
  product dimension (no snowflake), an explicit **Unknown customer** row for guest orders and a full-year date table
- the semantic model is written in **TMDL** (text files you can diff and review): single-direction many-to-one
  relationships, hidden keys, a marked date table, a role-playing ship date (inactive relationship), measures with
  format strings, implicit measures discouraged
- **`star-lint`**, a small .NET tool built on the Tabular Object Model (TOM), reads the TMDL folder and checks nine star
  schema rules. Errors fail the build with exit code 1 (a many-to-many relationship, no marked date table, a
  `sourceColumn` that isn't in the CSV); snowflake chains, bi-directional relationships, visible keys and measures
  without a format string are warnings

## The model

```
            Date (marked, 2024-01-01 .. 2026-12-31)
              │ 1        ┊ 1 (inactive: Ship Date, use USERELATIONSHIP)
              ▼ *        ┊ *
Customer 1 ─▶ *  Sales  * ◀─ 1 Product (Category > Subcategory > Product)
                   * ▲
                     │ 1
                   Store
```

Sales keeps `Order Number` as a degenerate dimension; every other fact column is hidden and summarized only through
measures (`Sales Amount`, `Total Cost`, `Margin`, `Margin %`, `Units`, `Orders`).

## Run it

```bash
# 1. data (already committed; regenerating gives byte-identical files)
cd src/data
python3 generate_export.py          # wrote 4071 rows
python3 build_star.py               # fact_sales 4071, dim_date 1096, dim_product 19, dim_customer 301, dim_store 5

# 2. lint the model (and regenerate the TMDL view script)
cd ..
dotnet run --project StarSchemaLinter -- ContosoSales.SemanticModel/definition --data data/star \
    --script ContosoSales.SemanticModel/TMDLScripts/create-model.tmdl
#   PASS SS001 ... PASS SS009   ->  0 error(s), 0 warning(s), exit code 0

dotnet run --project StarSchemaLinter -- ../tests/fixtures/snowflake-model/definition --data ../tests/fixtures/data
#   3 error(s), 7 warning(s), exit code 1

# 3. tests
cd ..
python3 -m pytest tests -q                       # 31 passed
dotnet test tests/StarSchemaLinter.Tests -m:1    # Passed: 17, Failed: 0
```

In the video, `star-lint` is short for `dotnet run --project src/StarSchemaLinter --` (the assembly is called
`star-lint.dll`).

Then, on Windows: copy `src/data/star` to `C:\MGLab\power-bi\star\` (or change the `DataFolder` parameter), open
`src/ContosoSales.pbip` in Power BI Desktop and **Refresh**. See [demo.md](demo.md) for the recording steps and the
expected numbers.

Expected totals after refresh (computed from the CSVs): **Sales Amount 1,862,401.98** (2024: 894,929.10 · 2025:
967,472.88), **Orders 2,440**, **Units 7,462**, Margin % 43.7 % in both years, Unknown customer 61,345.69.

## What we learned / gotchas

- **Relationships can't have `///` descriptions in TMDL.** Our first `relationships.tmdl` had one and TOM refused the
  whole folder: `Property 'description' is unknown and is not expected in the situation it appears.` Tables, columns,
  measures and expressions take descriptions; relationships don't.
- **Ship dates spill into the next year.** An order on 31 December 2025 ships in January 2026, so the date table must
  run to 31 December 2026 (it must also span full years and have no gaps). `build_star.py` derives the range from
  order *and* ship dates, and a test checks it.
- **Guest orders would become a "(Blank)" customer.** When a fact key has no match on the "one" side, Power BI adds a
  blank virtual row (an unknown member) to the dimension. We map guest orders to an explicit `Unknown customer` row
  (key -1) and a test proves every foreign key resolves.
- **Snowflakes are easy to miss in a diagram.** `star-lint` flags any dimension that filters through another one
  (`Product → Subcategory → Category`) and tells you which table to flatten.
- **Every partition passes `"en-US"` as the culture** of `Table.TransformColumnTypes`, because the CSVs use a decimal
  point and ISO dates whatever the regional settings of the PC that refreshes the model. Not yet observed in Desktop:
  demo.md step 4 checks that `47.40` loads as forty-seven point four on a machine with a decimal comma.
- **The PBIR report folder is hand-written and schema-validated, not yet opened in Desktop** (no Windows here). If
  Desktop rejects it, use the fallback in demo.md: blank report → TMDL view → paste `create-model.tmdl` → Apply →
  Refresh, then Save as PBIP. The TMDL view script doesn't carry model-level properties
  (`discourageImplicitMeasures`); set that one in Model view > Model explorer > semantic model properties.
