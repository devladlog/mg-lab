# DEVLADLOG Power BI #12: Paginated Reports

Same **Contoso Bikes** star as episodes 1-11. Dashboards are for screens; this episode builds the document that has to print
exactly as designed: a **store statement** as a paginated report (RDL), one A4 page per store with a repeating header and
"Page n of m", reading the published `ContosoSales` semantic model with a DAX query. Around it: a script that uploads and exports it
through the REST API, and a check that compares the exported PDF with numbers computed from the CSV files.

Blog guide: <https://www.devladlog.com/articles/power-bi/2025-05-07-paginated-reports-complete-guide-2025/>

**The report has never run.** The container has no Power BI Report Builder, no service and no DAX engine. The RDL is generated by a
script, validated against Microsoft's RDL schema and linted. Everything that needs the tenant is marked "needs tenant" below and
in [`demo.md`](demo.md).

## Rules (rdl_lint)

| Rule | Level | What |
|---|---|---|
| RL000 | error | not valid against the RDL 2016/01 schema |
| RL001 | error | body width + left and right margin is wider than the page: blank pages in PDF and Word |
| RL002 | warning | a tablix without a header row that repeats on new pages (`RepeatOnNewPage` + `KeepWithGroup`) |
| RL003 | error | a `@parameter` in the DAX without a `QueryParameter`, or bound to a report parameter that doesn't exist |
| RL004 | error | a password, user id or GUID in the connection string |
| RL005 | warning | no `Globals!PageNumber` in the page footer |
| RL006 | error | `Fields!X.Value` where the dataset has no field X |
| RL007 | info | a grouped tablix without any page break |
| RL008 | error | a size that is not a number with a unit (`6.5inin`) |

## What we learned / gotchas

- **Blank pages come from the body width.** Learn: *report body width <= page width - (left margin + right margin)*. The report here is 6.5in in a 6.77in usable width; RL001 applies the formula before you upload.
- **Repeating headers are tablix member properties**, not table settings: `KeepWithGroup = After` and `RepeatOnNewPage = true` on the static rows (Learn, Advanced mode of the Grouping pane). `RepeatOnNewPage` isn't supported for column group members.
- **The data source is the model, by name.** Learn's connection string for a Power BI semantic model is `Data Source=powerbi://api.powerbi.com/v1.0/myorg/<workspace>;Initial Catalog=<model>` with the Analysis Services type and no credentials. The file carries no dataset id.
- **A DAX dataset parameter** is a query parameter (`@Year`) bound to a report parameter; the measures stay in the model.
- **Upload (Imports - Post Import In Group):** `datasetDisplayName` is the file name with `.rdl`; for .rdl the name conflict can only be `Abort` or `Overwrite`; Learn also suggests the C# SDK for .rdl uploads.
- **Export (Export To File In Group):** `paginatedReportConfiguration` has `parameterValues` (strings), `identities` (required when the report uses a Power BI semantic model) and `formatSettings`. The job is asynchronous: start, poll the status, get the file. With Premium Per User the API allows one request per five minutes; 250 concurrent renders otherwise.
- **A downloaded PDF isn't a correct PDF.** The contract is computed from the CSV files, not from the report, so the check is independent of the thing it checks. `Margin %` is rounded half-even in Python and by the report's own format, so a difference in the last digit is possible and would be shown.

## Not verified

- **The RDL has never been opened in Power BI Report Builder or the service.** It validates against the XSD and passes the lint, which says nothing about whether the renderer accepts it.
- **No DAX has run.** The `DataField` names of the dataset (`Store[Store]`, `Date[Month Number]`, `[Sales Amount]`, ...) and the name of the query parameter (`@Year`) follow what the DAX designer writes, from knowledge, not from a test. If they differ, Report Builder shows it on the first run.
- `rd:SecurityType` `None` with `IntegratedSecurity` true is the "Do not use credentials" setting of Learn's connection string table; how the service authenticates the viewer is untested.
- The raw multipart upload of an .rdl (`Invoke-PowerBIRestMethod -InFile` with a hand built body) is asserted against a mock. Learn suggests the SDK for .rdl; if the service refuses the raw upload, use Report Builder's Publish.
- An export of a report on a semantic model needs an identity (Learn); which `username` the lab accepts, and the XMLA endpoint settings Learn mentions, are open.
- The PDF check ran only on a **simulated** PDF (reportlab, drawn from the contract). The real layout may wrap, shift or format differently, and the text extraction may need adjusting.
- The MicrosoftPowerBIMgmt module isn't installed here: `Invoke-PowerBIRestMethod` is mocked.
