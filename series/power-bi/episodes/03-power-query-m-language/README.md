# DEVLADLOG Power BI #3: Power Query & M Language

Same fictional **Contoso Bikes** data as [episode 1](../01-data-modeling-star-schema/) and
[episode 2](../02-advanced-dax/), but this time the source is what an ERP really drops in a folder: **24 monthly CSV
exports**, messy on purpose. The star schema that Python built in episode 1 is now built **in Power Query M, inside
the semantic model**. We prove it rebuilds exactly the same star.

- **Messy exports**: semicolons, decimal comma, `dd/MM/yyyy` dates, a `TOTAL` footer row, lower-case product codes with
  a trailing space from the online shop, empty customer codes for guest orders, a stray `_README.txt`, and each file
  **re-exports the last two days of the previous month** with corrected quantities (247 duplicated order lines)
- **Nine M queries** (`src/queries/*.pq`): a parameter, two **custom functions** (`fnReadExport`, `fnDimension`), a
  **staging query** that combines the folder and keeps the newest copy of each line (`Table.Sort` → `Table.Buffer` →
  `Table.Distinct`), and the five tables the model loads (`Product`, `Customer`, `Store`, `Date`, `Sales`)
- `tools/sync_tmdl.py` copies the `.pq` files into the **TMDL** model (shared expressions + M partitions), so the
  query files are the single source of truth
- **`pq-lint`**: a TypeScript linter on top of Microsoft's open-source
  [Power Query parser](https://github.com/microsoft/powerquery-language-services/tree/master/packages/powerquery-parser) (`@microsoft/powerquery-parser` 5.1.0)
- **`tmdl-check`**: a .NET tool on the Tabular Object Model (TOM) that loads the TMDL folder and checks that every
  partition and shared expression is exactly the `.pq` file
- a **Python mirror** of every M step that computes what Desktop must load, and tests that it equals the episode 1 star

## The queries

```
ExportFolder (parameter) ──▶ SalesExport (staging, not loaded) ──┬──▶ Product  ─┐
fnReadExport (function) ─────┘   Folder.Files → CsvOnly → Read   ├──▶ Customer ─┤ (keys)
                                 → Combine → Newest → Buffer     ├──▶ Store    ─┼──▶ Sales
                                 → Distinct(order, line)         └──▶ Date      │
fnDimension (function) ──────────────────── Product, Customer, Store ───────────┘
```

| pq-lint rule | Severity | Checks |
|---|---|---|
| PQ001 | error | syntax (the parser's own message and line) |
| PQ002 | error | a name that isn't a step, function argument, record field, `each` `_` or another query in the folder |
| PQ003 | warning | absolute path in `File.Contents` / `Folder.Files` / `Folder.Contents` (use a parameter) |
| PQ004 | warning | `Table.Distinct` on the result of `Table.Sort` without `Table.Buffer` |
| PQ005 | warning | `Table.TransformColumnTypes` without the culture argument |
| PQ006 | warning | `Folder.Files` and no filter on `[Extension]` anywhere in the query |
| PQ007 | warning | step names the editor generates (`#"Changed Type1"`, `#"Sorted Rows"`, `#"Expanded …"`) |
| PQ008 | warning | `Date.FromText`-style format with a culture and an unquoted `/` or `:` |

## Run it

```bash
# 1. data (already committed; regenerating gives byte-identical files)
python3 src/data/make_monthly_exports.py      # wrote 24 monthly files (4318 order lines, 247 re-exported) + _README.txt
python3 src/reference/pq_reference.py         # expected numbers -> src/reference/expected/summary.json

# 2. queries -> model, lint, TOM check
python3 src/tools/sync_tmdl.py --check        # TMDL in sync with queries
cd src/pq-lint && npm ci --no-audit --no-fund && npm test     # tsc + node --test: 12 passed
node dist/src/cli.js ../queries --strict                       # 9 queries: 0 error(s), 0 warning(s), exit 0
node dist/src/cli.js ../../tests/fixtures/ui-generated         # 3 queries: 3 error(s), 10 warning(s), exit 1
cd ..
dotnet run --project TmdlCheck -- ContosoSales.SemanticModel/definition queries \
    --script ContosoSales.SemanticModel/TMDLScripts/create-model.tmdl
#   5 table(s), 4 expression(s), 5 relationship(s): 0 error(s)

# 3. tests
cd ..
python3 -m pytest tests -q                    # 40 passed
dotnet test tests/TmdlCheck.Tests -m:1        # Passed: 7, Failed: 0
```

In the video, `pq-lint` is short for `node src/pq-lint/dist/src/cli.js`.

Then, on Windows: copy `src/data/exports` to `C:\MGLab\power-bi\exports\` (or change the `ExportFolder` parameter),
open `src/ContosoSales.pbip` in Power BI Desktop and **Refresh**. See [demo.md](demo.md).

## What we learned / gotchas

- **`Table.Distinct` doesn't promise which duplicate it keeps.** Learn says so explicitly ("you can't assume that the
  first row with a unique set of column values will remain") and recommends `Table.Buffer` first when it matters.
  Here it matters: keeping the older copy of the 247 re-exported lines gives 1,902,513.76 instead of 1,862,401.98.
  `fnDimension` uses `Table.Distinct` over *all* columns, where the survivor doesn't matter; if an attribute ever
  disagrees for the same code, refresh fails on a duplicate key on the "one" side instead of silently picking one.
- **In a custom date format, `/` is the culture's date separator, not a slash** (Learn: custom date and time format
  strings). Power BI's locale guidance shows pt-PT short dates as `31-12-2022`. `fnReadExport` quotes it:
  `"dd'/'MM'/'yyyy"`. PQ008 flags the unquoted form. We have not observed the unquoted form fail on Desktop yet
  (demo.md step 6 tries it).
- **`#date`, `#duration` and friends reach the parser as identifier expressions.** Our first `pq-lint` run reported
  them in `Date.pq` as unresolved names; PQ002 now skips hash keywords. Running the linter on our own queries found
  the bug before any fixture did.
- **The standard library is all dotted names** (`Table.Sort`, `Int64.Type`, `Order.Descending`), so PQ002 only needs
  to resolve undotted names: steps, parameters, `each` (`_`), record fields (they can see each other in M) and other
  queries. It's a scope walker, not an evaluator.
- **CSV files don't fold** (Learn: sources without a query engine, such as CSV and Excel, don't support query
  folding), so every step here runs in the mashup engine. With a SQL source, the order of steps would matter for
  folding; here it matters for correctness only.
- **Filter `Folder.Files` by extension, lower-cased.** Learn's combine files guidance recommends filtering the file
  list (for example on Extension); `Text.Lower` also catches `.CSV`. A test drops a `notes.txt` and an upper-case
  `.CSV` into the folder to prove it.
- **Not verified on this machine (needs Power BI Desktop on Windows):** the M never ran here. The parser validated
  the syntax, `pq-lint` the names, TOM the TMDL, and the Python mirror the logic. Watch on first refresh:
  `Date.FromText` with the quoted format, `Currency.Type` with `"pt-PT"` on `47,40`, `Csv.Document` with
  `Columns = 19`, `Table.InsertRows` with a record, and whether Desktop shows the shared expressions as queries
  with load disabled. demo.md lists the expected numbers to compare.
