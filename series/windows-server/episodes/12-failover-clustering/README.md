# DEVLADLOG Windows Server #12 — Failover Clustering: check the nodes, read the plan, build it, measure the failover

Episode 11 let people sign in to one server; this one keeps a service up when a server goes away. One module,
**ClusterLab**, driven by [`src/cluster-lab.json`](src/cluster-lab.json), for a two-node cluster of Server Core VMs
(`CON-NODE01`, `CON-NODE02`) with a file share witness on `CON-SRV01` and one clustered role, the IIS service `W3SVC`
(no shared disk, so no storage to buy):

1. **Check.** A read-only collector runs on each node (build, installation type, domain, clock, addresses, pending
   reboot, feature state, cluster service) and checks the witness share. `Test-ClfReadiness` turns the facts into findings
   (High / Medium / Low / Info): not domain-joined, different domains, clocks further apart than Kerberos tolerates, a
   cluster or role address that is not on the node network, DHCP addresses, different builds or editions, a node that is
   already clustered, a missing witness for an even node count.
2. **Quorum arithmetic.** `Get-ClfQuorumMath` is the static vote count (two nodes: 2 votes, no node can be lost; with a
   witness: 3 votes, one can). It is printed with every check and says it is static.
3. **A plan before any change.** `Get-ClfBuildPlan` lists the steps in a working order (feature, IIS, index page,
   `Test-Cluster`, `New-Cluster`, witness share, `Set-ClusterQuorum`, clustered role), drops what is already done, and
   marks the steps that **cannot run remotely** (`LocalOnly`) and the ones that **create AD objects**.
4. **Apply with -WhatIf.** `Invoke-ClfPlan` runs one step at a time, only six allow-listed cmdlets, and refuses to start
   on a machine that is not a cluster node when the plan has a local-only step.
5. **Drain and measure.** `Invoke-ClfDrain` pauses the owning node with `-Drain`, shows where the role went, resumes the
   node without failback. `Invoke-ClfProbe` (HTTP prober) and `Get-ClfProbeSummary` measure the outage from the outside.

## Design choices

- **Same shape as episodes 1 to 11.** A collector that only reads (a test fails if it calls a `Set-/Remove-/Install-/
  New-/...` cmdlet), pure rules, a report, a plan, an apply with `-WhatIf` and an allow-list.
- **Build on a node.** Learn: `New-Cluster`, `Add-ClusterGenericServiceRole` and `Remove-Cluster` cannot be run remotely
  without CredSSP. Instead of enabling CredSSP, those plan steps are marked `LocalOnly` and `Invoke-ClfPlan` throws
  ("Run it ON a cluster node") before changing anything when it is started elsewhere.
- **The witness share is created after the cluster.** The cluster name object has to exist before it can be given access
  (Learn: change on the share, modify on the folder), so the plan order is cluster, share, quorum, role.
- **A witness on a node is rejected on load.** Learn: the file share witness belongs on a Windows server in the same
  forest, physically separate from the nodes, and DFS is not supported.
- **No shared storage.** `New-Cluster -NoStorage`, `Test-Cluster -Ignore Storage`, and a role that needs no disk. A real
  file server or SQL cluster adds storage and its validation tests.
- **Idempotent.** The plan is rebuilt from the facts on every run: a node that already runs the cluster service skips
  validation and creation, so a restart halfway through needs no bookkeeping.
- **Drain, then no failback.** `Suspend-ClusterNode -Drain -TargetNode -Wait`, then `Resume-ClusterNode -Failback
  NoFailback` (Learn parameters), so the role stays where it went.
- **Measure from the outside.** The prober asks the clustered address, records who answered, and the summary counts an
  outage from the first failed request to the next good one.

## What we learned / gotchas

- **Two nodes and no witness cannot lose a node.** Two votes, quorum needs both. A witness makes it three votes and one
  node can go. Learn recommends a witness for 2012 R2 and later and says Dynamic Quorum manages votes, so the check's
  number is labelled static.
- **Not remotely.** See the design choices; this is the episode's gotcha scene.
- **Kerberos and the clocks.** Learn gives a default clock skew of 5 minutes; a larger spread is flagged High. All nodes
  must be in the same domain.
- **The prober measures about two seconds at best.** A failed request waits for its timeout (2 s here), so one outage is
  accurate to about that much, not to the millisecond. Lower `-TimeoutSec` for a finer picture, at the price of false
  failures on a slow node.
- **Test-Cluster warns without shared storage.** We ignore the storage category; read the rest of the report instead of
  only the verdict.
- **PowerShell parse trap.** `"$n:"` reads as a drive-qualified variable; write `"${n}:"`. It broke the module on the
  first run (the same class of mistake as in earlier episodes).
- **Pester and PowerShell 7.** `Invoke-WebRequest` returns `Content` as bytes when the server sends no content type; the
  prober decodes both, and the test listener sets `text/plain`.
- **Pester and modules.** Mocks of cmdlets the module calls need `-ModuleName ClusterLab`, and the global stubs need
  `SupportsShouldProcess` and the parameters the module splats.
