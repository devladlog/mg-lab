# DEVLADLOG Windows Server #8 — Windows Server security: check the baseline, read the plan, then change it

Episodes 1 to 7 built the lab; this one hardens it, without clicking through twenty policy dialogs. One module,
**SecLab**, driven by [`src/sec-lab.json`](src/sec-lab.json):

1. **Baseline check.** A read-only collector runs on each server over WinRM (SMB signing and SMB 1, LmCompatibilityLevel,
   WDigest, whether Credential Guard is running, LDAP signing on domain controllers, the Process Creation audit setting
   and the command-line switch, Defender status, Windows LAPS policy). `Test-SecHost` turns the facts into findings
   (High / Medium / Low / Info) with a fix id where one is safe to automate.
2. **A plan before any change.** `Get-SecRemediationPlan` turns findings into steps (target, what, value now, value
   after) and `Get-SecRollbackPlan` writes the reverse from the values it read. The risky step (NTLMv2 only,
   `LmCompatibilityLevel` 5) is left out unless you add `-IncludeRisky`.
3. **Apply with -WhatIf.** `Invoke-SecRemediation` runs one remote step at a time (registry, `Set-SmbServerConfiguration`,
   `auditpol`), with `-WhatIf`, and the rollback file undoes it.
4. **Windows LAPS in Active Directory.** `Get-SecLapsPlan` lists the steps (schema, OU permission, GPO, three policy
   values, link) and `Invoke-SecLapsPlan` runs them. The schema update is forest-wide, so it is skipped unless
   `-AllowSchemaUpdate` is given and is left out of the plan when the schema already has it.

## Design choices

- **Read first, change second.** Same shape as episodes 1 to 7: a collector that only reads, pure rules, a report. The
  new part is the plan: every change is a row you can read, and every row remembers the value it replaced.
- **Our policy in the JSON, Microsoft's values in the code.** "Require SMB signing", "NTLMv2 only" and "signatures at
  most 7 days old" are our policy. LAPS ranges (age 1 to 365 days, length 8 to 64), the `BackupDirectory` meanings and
  the Group Policy registry root come from Learn and are checked on load.
- **A finding is not always a fix.** Credential Guard, Defender and the LDAP policy are reported but never changed by
  script: they depend on hardware, licences or Group Policy and have their own tooling.
- **The audit setting is addressed by GUID.** `auditpol` takes the subcategory GUID, so the Process Creation setting
  is read and written without depending on the language of the server. Only the returned text ("Success") is
  matched, and a server that answers in another language gets an Info finding, not a wrong one.
- **Risky is opt-in.** Level 5 makes domain controllers refuse LM and NTLM (Learn): anything still on NTLM stops
  authenticating. The plan leaves it out until `-IncludeRisky`.
- **One irreversible step, behind a switch.** Windows LAPS needs a one-time, forest-wide schema update. The script
  checks for `ms-LAPS-Password` first and only runs `Update-LapsADSchema` with `-AllowSchemaUpdate`.

## What we learned / gotchas

- **Learn disagrees with itself about SMB signing on Windows Server 2025.** "Control SMB signing behavior" says
  Windows Server 2025 requires *outbound* signing only. "SMB security hardening" says all outbound *and inbound*
  connections are required to be signed by default. Instead of trusting either, the check reads the real
  `Get-SmbServerConfiguration` / `Get-SmbClientConfiguration` values. Requiring signing also disables guest access
  (Learn), so third-party SMB servers can stop working.
- **A missing LDAP signing value is not a finding.** Learn: Windows Server 2025 requires LDAP signing by default for
  new deployments, with an enforcement policy that takes precedence, and a DC upgraded without a signing policy takes
  the default. So no `LDAPServerIntegrity` is Info ("check the Group Policy result"); only an explicit 0 is High.
  The registry location we read on the DC is a hint, not a ruling (see "Not run yet").
- **Credential Guard is on by default on Windows Server 2025, with conditions.** Domain-joined, not a domain
  controller, hardware and licence requirements met, not explicitly disabled; an explicit disable before the upgrade
  stays in force. A Hyper-V VM needs generation 2 and the host an IOMMU (Learn). "Not running" on a lab VM is
  therefore a hardware question first.
- **Command-line auditing writes secrets to the Security log.** Event 4688 needs both *Audit Process Creation* and
  *Include command line in process creation events*, both off by default; once the second is on, everyone who can
  read the Security log can read every command line (Learn's own warning).
- **`Update-LapsADSchema` is a one-time operation for the entire forest** (Learn) and asks before adding each
  attribute. We treat it as irreversible: the plan skips it when `ms-LAPS-Password` exists, and the apply function
  refuses without `-AllowSchemaUpdate`.
- **Windows LAPS processes policy once an hour**, not on the Group Policy refresh. `Invoke-LapsPolicyProcessing` starts
  a cycle; event 10018 in *Windows LAPS > Operational* means the password was written to Active Directory. With
  `ADPasswordEncryptionEnabled` (default True) the domain functional level must be 2016 or later.
- **LAPS GPO values live under `HKLM\Software\Microsoft\Windows\CurrentVersion\Policies\LAPS`**, and the CSP root
  (`HKLM\Software\Microsoft\Policies\LAPS`) wins if even one setting is configured there, so Intune-managed settings
  can hide the GPO. `BackupDirectory` defaults to Disabled, so a policy without it does nothing.
- **A pure "Windows Server 2025 default" check would have been wrong in both directions.** Defaults differ by OS
  version and by upgrade versus new deployment; the rules say what the policy wants and what was found.
- **The PowerShell parser again.** `"... is $lm: clients ..."` is a drive-qualified variable and stops the module
  loading; `${lm}:` fixes it (episodes 6 and 7 hit the same rule).
- **Pester must mock the real parameters.** A stub for `Update-LapsADSchema` needs `SupportsShouldProcess`, or the
  `-Confirm:$false` we pass makes the mock fail to bind.

> property names, `Win32_DeviceGuard`, `auditpol /get ... /r` column name and text, `Get-MpComputerStatus`, the

> rollback, and the whole LAPS path (RSAT modules, schema update, OU permission, GPO creation and link, event 10018,
> `Get-LapsADPassword`). Only parsed and unit-tested here.
