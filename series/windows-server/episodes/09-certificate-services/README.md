# DEVLADLOG Windows Server #9 — Certificate Services: build an enterprise CA, then check it before it checks you

Episodes 1 to 8 built and hardened the lab. This one gives it a certification authority and a way to look after it.
One module, **CertLab**, driven by [`src/cert-lab.json`](src/cert-lab.json):

1. **Certificate check.** A read-only collector runs on each server over WinRM and reads the machine store
   (subject, issuer, validity, key and signature algorithm, EKUs, SAN, template name, CRL distribution points).
   `Test-CertHost` turns that into findings: expired, expiring (30-day warning, 14-day critical), weak signature or key,
   self-signed, no private key, issued by the CA with no HTTP CRL location.
2. **CA check.** A second collector runs on the CA (service state, the CA certificate, the newest base CRL, the CDP list
   from `Get-CACrlDistributionPoint`, the published templates with their flags, EKUs and enroll permissions read from
   Active Directory). `Test-CaFacts` flags a stopped service, an expiring or weak CA certificate, a CRL that is expired or
   about to be, no HTTP CDP, local or UNC paths in issued certificates, and the template rule below.
3. **The template rule.** `Test-CaTemplate`: if the requester supplies the subject or the subject alternative name,
   the certificate can sign someone in (client authentication, smart card logon, any purpose, or no EKU), nobody approves,
   and a broad group (Domain Users, Domain Computers, Authenticated Users, ...) can enroll, that is **High**. With approval
   or a named group it is a **Low** note.
4. **Renewal plan.** `Get-CertRenewalPlan` turns expiring certificates into steps: **Enroll** (`Get-Certificate -Template`
   on the owning server) when the certificate has a template name and is not self-signed, **Manual** for everything else.
   `Invoke-CertRenewal` honors `-WhatIf` and never runs Manual steps.
5. **CA build plan.** `Get-CertCaPlan` / `Invoke-CertCaPlan`: role service, enterprise root CA, CRL periods; then IIS virtual
   directory, HTTP CDP, publish. The step that writes to Active Directory is marked irreversible and refuses to run without
   `-AllowCaInstall`.

## Design choices

- **Same shape as episodes 1 to 8.** A collector that only reads, pure rules, a report, a plan before any change. A test
  proves the collectors call no command with a changing verb (the only deletion is their own temporary CA-certificate file).
- **Facts are saved as JSON**, so the same rules re-run offline: that is how the tests and the sample reports work.
- **The template rule reads flags, not names.** The constants come from Learn (`SubjectNameEnrolleeSupplies` 0x1,
  `SubjectAlternativeNameEnrolleeSupplies` 0x10000, `EnrollmentPendAllRequests` 0x2, the Certificate-Enrollment right
  `0e10c968-78fb-11d2-90d4-00c04f79dc55`); which groups count as "broad" is our policy, in the JSON.
- **A fix is not always a script.** `Add-CATemplate` only publishes an existing template; it cannot create or duplicate one
  (Learn). So the check reports a bad template and the fix is a console step recorded in demo.md, not a function.
- **Irreversible behind a switch.** An enterprise CA is integrated with AD DS and Install needs an Enterprise Admin
  (Learn). The plan marks it, and `Invoke-CertCaPlan` stops there without `-AllowCaInstall` (later steps would fail anyway).
- **HTTP CDP, but only as a lab shortcut.** Learn says to publish an HTTP CRL location and notes that the cmdlets neither
  create a web server nor copy files. The lab serves `CertEnroll` from IIS on the CA itself; say on camera that a real
  deployment separates the CA from the web server.

## What we learned / gotchas

- **Learn's example for `Install-AdcsCertificationAuthority` does not run as printed.** Examples 2 and 3 write
  `CAType = EnterpriseRootCa` and `HashAlgorithmName = SHA256` without quotes. PowerShell treats a bare word in a hashtable
  value as a command (`The term 'EnterpriseRootCa' is not recognized...`, reproduced in PowerShell 7). The script still
  *parses*, so a parse test would not catch it: the tests check that the generated script has the values quoted.
- **`KeySize` is write-only through the PowerShell 7 adapter** on the RSA object returned by
  `RSACertificateExtensions.GetRSAPublicKey` (`Cannot get property value because "KeySize" is a write-only property`).
  The collector computes the size from `ExportParameters($false).Modulus`, which works in 5.1 and 7. Found only because the
  collector is tested on real certificates, not fixtures.
- **This build container refuses to sign with SHA-1** (`'SHA1' is not a known hash algorithm`), so the SHA-1 and MD5
  signature rule is covered by the fixtures only; the real-certificate tests use a 1024-bit key and SHA-384 instead.
- **Changing a CDP only affects certificates issued afterwards** (Learn). The check therefore reports the CA setting
  (`CdpNoHttp`) and, per certificate, `CertNoHttpCdp`; renewing is what fixes the second.
- **Revocation is not instant** (Learn): `certutil -CRL` writes the CRL, it does not prove that the web server serves it.
  Verify with `certutil -verify -urlfetch` from a client network (the demo does).
- **The CRL check parses `certutil -dump` text** (`NextUpdate:`), which is localized on non-English servers; the collector
  then returns a `CollectorError` row instead of a wrong answer.
- **Learn's CAPolicy.inf page spells the registry change as `Certutil -setreg CACRLPeriod Weeks`**; `certutil -setreg`
  addresses the CA key as `ca\` (alias list on the certutil page), so the plan uses `CA\CRLPeriod`.
- **The v2 template extension prints as `Template=<name>(<oid>)`**, and the name there may be the display name, not the
  short name that `Get-Certificate -Template` wants. The renewal plan prints the template it will use; check it against
  `Get-CATemplate` the first time.
- **KB5014754 (certificate-based authentication on domain controllers)** is not part of this check. Learn's Intune pages
  only say the KDC requires a strong mapping (a SID extension) and denies authentication that lacks it after the
  full-enforcement date; read the KB for the dates before issuing client-authentication certificates.

> **Not run yet (needs the lab, see [demo.md](demo.md)):** both collectors on real servers (`Get-CACrlDistributionPoint`
> and `Get-CATemplate` property names, `certutil -ca.cert` and `-dump` output, the ADSI template and ACL reads,
> the `Cert:\LocalMachine\My` extension formats), the CA build (`Install-AdcsCertificationAuthority` on Server Core, the
> `certutil -setreg` periods, the IIS virtual directory and `.crl` mapping, `Add-CACrlDistributionPoint` and whether
> `Get-CACrlDistributionPoint` returns the `<CAName>` tokens as written), `Get-Certificate` through `Invoke-Command`
> (it may need delegation: Learn), and the whole renewal path. Only parsed and unit-tested here.
